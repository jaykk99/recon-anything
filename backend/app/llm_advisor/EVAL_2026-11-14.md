# LLM advisor eval — 2026-11-14 (live, this VM)

## Question

Which free/keyless uncensored model is the smartest RELIABLE choice for
ReconAnything's advisor/investigator work (thinking + coding)? Measured,
not marketed.

## Method

Each candidate was called DIRECTLY (not via the Bro gateway chain, so
per-model numbers are visible), on the same 3 tasks, same prompts,
temperature 0.2 (code retest 0.1):

- (a) **reason** — rank 3 REAL findings from
  `~/workspace/recon-continuous/results/candidates.jsonl` (lines 2, 1,
  116: `recipient_mint_to_caller` 0x15f7…e66b Arbitrum `mint`;
  `access_control_flaw` 0x13a7…df1d Arbitrum `withdraw`;
  `uups_authorize_upgrade_missing` 0xc19d…48e50 BSC `_authorizeUpgrade`,
  all UNVERIFIED), state missing evidence + one read-only check each.
- (b) **code** — write stdlib-only `detect_unguarded_mint(source) -> dict`.
  Scored by actually running it: must compile, flag unguarded
  `_mint(to, amount)`, and clear `onlyOwner` / `require(msg.sender ==
  owner)` guarded versions.
- (c) **explain** — plain-terms explanation of an unguarded mint, <120 words.

Scoring per task: correctness 0-2, usefulness 0-2. Any refusal or
evasion = fail for that task. Failed cells were retried once (code
retried a second time for the 3 Horde models). Raw outputs:
`/tmp/llm_eval_results.jsonl` (this VM only, ephemeral).

## What the numbers mean

- **Reasoning (the advisor's main job): MeroMero wins clearly.** Its
  ranking was the only one with per-finding specifics: it named the
  EIP-1967 implementation slot (`cast storage … 0x36`) for the UUPS
  case, the exact missing evidence per finding (function signature /
  source), and a distinct read-only check per finding. Heretic's
  ranking was correct in outline but generic (same `cast eth_call`
  advice for all three, vague "0x selector"). OVH's ranking was cut
  off at 246 chars: gpt-oss spends the token budget on hidden
  reasoning, so with max_tokens 600 almost nothing is left for the
  answer. Rocinante's reason task failed twice on transport, no data.
- **Code: NO model passed.** Heretic and Rocinante both returned
  complete, compiling detectors with sound-looking structure, but both
  only match single-argument `.mint(x)` forms and miss the standard
  OpenZeppelin shape `_mint(to, amount)` — false negative on the
  unguarded sample, in two independent attempts each. MeroMero's one
  returned code sample degenerated into repeating
  `onlyOwner|onlyRole|…|Authorized|Admin|Minter…` until the token
  budget ran out (SyntaxError). Kilo/OVH code attempts died on
  truncated JSON (see below). Consequence for the wiring: detector
  code from any model is treated as untrusted text — `draft_detector`
  compile-checks it and the caller must run it before trusting it.
- **Explain: all five models that answered were correct.** Kilo's was
  the most concrete (dump on DEXs, drain liquidity pools); MeroMero,
  OVH and Rocinante were solid; Heretic's was correct but thin.
- **Refusals: zero.** No model refused or deflected on any answered
  call. Every failure was a transport/provider error, not a refusal.
- **Reliability is the weak point everywhere, and it is shared.**
  Horde anonymous calls fail ~40% of the time right now with
  `Remote end closed connection without response` (heretic, rocinante)
  or `IncompleteRead` (meromero once). Qwen3-14B is 403 FORBIDDEN on
  all 6 attempts — its worker is dead/forbidden today, do not use.
  LLM7 is 429 on all 6 attempts — rate-limited out today. Kilo and
  OVH close the connection mid-body on longer replies, producing
  truncated JSON (`Unterminated string…`); short replies work. That
  is why the wiring is a CHAIN with per-backend retry, and why the
  advisor keeps max_tokens low (<=600) for the gpt-oss backends.

## Winner

**MeroMero-26B (`koboldcpp/G4-MeroMero-26B-A4B-it-uncensored-heretic`,
AI Horde, anonymous keyless).** Best reasoning by a clear margin, good
explanations, zero refusals. Its failures were the same transport
flakiness every Horde model showed, not capability gaps.

no change. Groq would be the obvious first key to add: gpt-oss-120b
behind a real API instead of the flaky OVH endpoint.
